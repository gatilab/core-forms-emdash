## Contract decisions so far (to record in AGENTS.md "Contract notes")

- Route access rules live with the I/O types: each `api/<module>.ts` has a `RouteSpec` table (kind, method, body, raw, owner, module, scope, MCP). `ROUTES.md` is generated from these, not from server code, so gen-routes never imports server code.
- Leaf records that must nest in `WpValue` (`SealedSecret`, `FieldCondition`, `FieldOption`, `ActionCondition`, `RecipientRoute`, `FileDescriptor`) are `type` aliases, not interfaces (shape unchanged).
- Body modes: `headless/submit` and `drafts/load` use `bytes` (they accept JSON or form bodies). `polls/results`: `?poll_id=` → AJAX envelope, `?id=` → REST shape.
- `internal/go` lives in P1.6's `submit` module. MCP `forms_export` maps to `data/export-page`.
- Additive outputs beyond §8.2: `forms/list.stats` (stats strip, spec 04 §1.3.1), `forms/get.defaults`, `internal/render.private` (DV-50), `emailLogs.resendOf` (DV-33 link field).
- Poll `settings` stored with WP keys (D-012), not spec 03 §10.1's camelCase. `team.assignee` is an EmDash user id string or null (WP 0).
- Port implementers: P1.0b owns `SubmissionRepo` and `ThemeStore`; P1.7 `FormRepo`; P1.10 `FileStore`/`FileReader`; P1.11 `Mailer`; P1.19a `ReplyStore`.
- `core/html` will expose domhandler node types as its tree (planned; not yet written).
- Planned `uniqueIndexes` rule: declare them only where WP has a UNIQUE key **and** §6.2 lists a `uniques` claim (Phase 4: products.slug, plans [productId,slug], orders orderNumber/sourceKey, licenses licenseKey, activations [licenseId,siteHash], packages [productId,version], subscriptions licenseId). Replies and actionLogs dedupe by deterministic id instead (a unique index would throw on legitimate null/event rows).
