# P1.1 WP oracle & golden corpus: handoff (paused)

Status: **paused early in the environment step.** No golden sets and no fixtures exist yet. Branch `pkg/p1.1`, worktree `../core-forms-emdash-wt/p1.1`.

## Environment chosen

WordPress Playground's php-wasm, driven **in-process** from our own Node script through `@php-wasm/node` and `@wp-playground/wordpress` 3.1.56. It does not use the `wp-playground-cli` binary, because the CLI runs PHP in worker threads and always calls `api.wordpress.org` to resolve the version.

- PHP 8.3.33 (wasm), **libxml 2.9.10**, with DOM, mbstring, intl, sqlite3 and pdo_sqlite. The DOMDocument round trip of `<p><div>…`, booleans and entities matched native PHP 8.5 with libxml 2.9.13 on a smoke test.
- WordPress 7.1.2 (the zip is cached at `~/.wordpress-playground/7.1.2.zip`) on SQLite, through the `sqlite-database-integration.zip` bundled in `@wp-playground/cli`. A fresh install runs every time. Boot takes about 12.5 s.
- **Determinism (verified, two identical runs).**
  - Virtual clock: `Date.now()` returns `base + tick × 1 µs`. PHP time stays frozen to the second, and `uniqid()` can still advance. Don't wrap the sub-second part: that hangs the boot.
  - Seeded PRNG behind `crypto.getRandomValues`, so `random_bytes`, `wp_rand`, salts and hashes repeat exactly.
  - PHP calls `post_message_to_js({"op":"clock","t":…})` to set the time for each case, which the schedule matrix needs.
- Fallbacks were not needed: `@wordpress/env` (Docker) and local PHP 8.5 with libxml 2.9.13.

Prototype: `tools/wp-oracle/bin/proto-runner.mjs`. Its header lists the prerequisites.

## Findings to carry forward

- `.reference/core-forms-wp` has **no `vendor/autoload.php`**, so the plugin bails without one.
  - The oracle must stage a copy of the plugin and add a generated autoloader: a classmap of every class file in `src/`, plus the extension class files that aren't `require`d explicitly (`extensions/file-upload/includes/class-upload-failure.php`). Composer "files" are `src/functions.php` and `src/templates.php`.
  - Never modify `.reference`.
- `Form::get_html()` uses `wp_unique_id('cf-form-{ID}-')`, the global counter that the normalizer handles. Random sources are listed by `grep` for `random_bytes|wp_rand|wp_generate_password|uniqid|wp_generate_uuid4`.
- Seed: prefer `emdash-next/migration/data/core-forms-data.json`, the native `core-forms-data` v1 export with all meta and `cf_settings`.
  - **Anonymize it before committing anything derived from it:**
    - every email outside markup becomes `userN@example.com`;
    - the 6 Activepieces webhook URLs become `https://hooks.example.com/N`;
    - every *non-empty* key, secret or token becomes `test_<key>_placeholder`. Only `headless.api_key` is set today. Keep empty values empty, or captcha and payment features switch on.
  - Markup emails are generic placeholders (`your@email.com`, `you@company.com`, `email@example.com`). Keep them byte-identical.
  - `cf_message_spam` on one form contains a real address.
  - Also produce a sanitized `core-forms.json`.
